# EchoCast 使用手册 · 客户端与服务端配置

> 面向两种角色：**终端用户**（想在桌面收通知）和**服务端管理员**（要搭/管服务端）。
> 协议细节见 [notice-protocol.md](notice-protocol.md)、路由见 [terminal-routing.md](terminal-routing.md)、
> 授权链路见 [auth.md](auth.md)——本手册只讲「怎么配」。

---

## 一、终端用户 · 三分钟跑通

前提：管理员已给你一个**激活码**（8 位，形如 `K6DZ-DW4X`，10 分钟内有效、只能用一次）。

1. **安装**：双击 `EchoCast_x64-setup.exe`（按用户装，免管理员）或 MSI（装 Program Files，需管理员）。安装完成托盘出现机器人图标。
2. **入网**：打开窗口 → 服务端卡：
   - 地址填管理员给的（`wss://服务器:端口/ws`；写 `host:port` 或 `http://` 会自动补全）
   - 点 **「没有令牌？用激活码入网 →」** → 输激活码 + 这台机器的别名（可空，默认计算机名）→ **激活并连接**
   - 成功后令牌自动写入，不需要手抄任何东西
3. **验收**：右下角弹出欢迎气泡即通。关掉窗口程序仍在托盘守着通知。

> 老方式（手填 token）：管理员直接给你 `net-` 开头的令牌 → 粘贴到「接入令牌」框 → 点「连接」。两种方式二选一。

### 1.1 客户端各配置项

| 配置 | 位置 | 说明 |
|---|---|---|
| 服务端地址 | 设置 → 服务端 | `wss://…/ws` / `host:port` / `http://…` 均可，自动归一 |
| 接入令牌 | 设置 → 服务端 | 与一台终端一一对应；留空 = 匿名，只收全员广播 |
| 激活码 | 设置 → 服务端 → 激活码入网 | 换新令牌的正规途径（一码一机、10 分钟时效） |
| 订阅类型 | 设置 → 服务端 → 折叠区 | 事件过滤器，默认全订阅；不动它 |
| 多端点 | 服务端卡下方 | 保存多套「地址+令牌+订阅」一键切换，适合内网/公网两套环境 |
| 本地演示服务端 | 设置 → 服务端 | 手边没服务端时点它，本机 127.0.0.1 起一个演示实例 |
| 显示方式 | 设置 → 显示方式 | **右下角气泡**（带形象/交付清单）或 **顶部灯条**（一行不挡内容） |
| 提示音 | 设置 → 提示音 | 开始/完成/警告/失败四态 + 问询音；静音三入口（喇叭按钮 / 面板 / `Ctrl+Shift+M`），静音是硬闸门 |
| 形象包 | 设置 → 形象包 | 内置 robot；导入用户包（`%APPDATA%\com.echocast.client\buddies\`）；定制管线随包分发 |
| 配置落盘 | 设置页底栏 | `%APPDATA%\com.echocast.client\settings.json`，点路径可复制 |

### 1.2 日常使用

- **气泡交互**：悬停 5 秒自动已读收起；点「已读」立即收；点卡片打开第一个交付物；**点 robot 弹「交付清单」**（全部链接/文件逐项打开）；点「📎 N 个文件」进详情面板（图片/音视频预览、文件下载）
- **问询**（需要你拍板的任务）：常驻不消失，气泡上直接点选项；「忽略」先放一边；答复回执经服务端确认（ack/nack/待确认三态）
- **托盘**：左键弹菜单（连接状态/静音/设置/消息回看/退出）；关窗口 = 缩托盘继续守
- **消息回看**：托盘 → 消息回看，最近 100 条按任务名搜索，点一条原样弹回桌面
- **排障帧日志**：设置页底栏路径 3 秒内连点 5 次 → 看服务端发的每一帧原文（含 token，截图外发注意）

### 1.3 报错对照

| 界面提示 | 含义 | 怎么办 |
|---|---|---|
| token 无效或已过期（401/4001） | 令牌填错/被吊销 | 别反复重试（客户端已自动停连）；找管理员要新激活码重新入网 |
| 终端已被其他实例占用（4029） | 同一令牌在别的机器在线 | 一台机器一个令牌；第二台找管理员再签 |
| 连不上服务端 | 地址错/网络不通 | 核对地址格式；地址前缀不是 ws 会被自动改写，注意提示行 |
| 连上了但没消息 | 订阅类型没对上 / 路由没到这台 | 打开帧日志看有没有帧到达；有帧没气泡→找管理员查字段，无帧→路由/订阅问题 |

## 二、服务端管理员 · 搭建与配置

### 2.1 部署形态

```
客户端 ── wss://bridge:8443/ws ──► bridge（TCP 透传，无鉴权逻辑）
                                      └─► orchestrator（唯一鉴权点：WS connection 事件）
                                            ├─ 终端注册表 network.json（只存 token 的 sha256）
                                            ├─ 任务路由（token→terminal 绑定，target 决定投递）
                                            └─ HTTP API（/api/*、/network/*）
```

要点：
- **鉴权只在一处**：orchestrator 的 WS connection 事件按 `sha256(token)` 查 `network.json`。bridge/NPM 等网关层不要加鉴权逻辑（曾把激活端点藏在管理台登录后导致用户调不通）
- **激活端点必须匿名可达**：`POST /api/terminals/activate`——激活码本身就是凭证（一次性+时效，fail-closed），套会话等于把用户挡在门外；建议加按 IP 限流
- 令牌明文**只在签发响应里出现一次**，库里只有哈希

### 2.2 终端注册（给用户发令牌）

**方式 A · 激活码（推荐，面向最终用户）**

```
管理员：EchoCast 看板 → 客户端页签 →「生成激活码」
        （或 API：POST /network/activation-codes）
   ↓    得 8 位码（10 分钟有效、一次性、一码一机）——微信/口头给用户
用户：  客户端设置 →「用激活码入网」→ 输码 → 自动换 token 并连接
```

> **用户从哪知道找谁申请？** 服务端可通过可选端点 `GET /api/server-info`
> 自述入网指引（`join_doc` 链接 + `contact` 联系方式，内容部署方全权定制）。
> 客户端在激活面板自动拉取并展示；服务端不提供则显示通用文案
> 「联系该服务端管理员」。两端解耦：客户端不假设任何发放流程，
> 只做展示。参考实现见 `tools/ws-demo.py`。

**方式 B · 直接签发（内部/应急）**

`POST /network/join`（需入网邀请码）→ 返回 `net-` 令牌给用户手填。

**吊销与找回**：管理员删除该终端在 `network.json` 的 agent 记录（=吊销，后续连接即断）→ 给用户新激活码重新入网（terminal_id 会换新）。换机器同此流程。

### 2.3 发通知（三条上行入口）

| 入口 | 配置 | 身份署名 |
|---|---|---|
| **HTTP 直发** | `POST /network/publish`，头 `Authorization: Bearer <net-token 或 api-token>` | `agent_name` = 入网注册名 / 令牌备注名 |
| **MCP 工具** | `echocast_notify`（编排 bearer） | `agent_name` = executor 或 body 覆写 |
| **webhook 桥** | 路由 secret（token/HMAC），白名单内会话 | `node_alias` = `webhook:<路由id>` |

**通知帧最小形状**（服务端 → 客户端）：

```json
{ "op": "notice", "notice": {
    "id": "task-001",              // 同 id 反复推 = 原地更新（进度不刷屏）
    "task": "合成配音第 9 段",
    "status": "running",           // running / success / failed（+progress 0–1）
    "executor": { "name": "Soundao" },
    "agent_name": "配音老王",       // 可选署名，≤20 字符超长客户端掩码
    "result": "已完成交付",
    "media": [ {"kind":"audio","url":"https://…/seg9.wav","name":"第9段.wav"} ]
} }
```

**投递目标**（`target` 字段，路由在服务端完成）：

| target | 效果 |
|---|---|
| `{"kind":"terminal","id":"term_xxx"}` | 精确一台 |
| `{"kind":"label","labels":["办公"]}` | 按标签一组 |
| `{"kind":"broadcast"}` | 全员 |

三个已知坑：`progress` 是 **0–1**（别给 62）；不知道进度就**整个省略**字段（给 `null` 会显示成「刚开始」）；媒体只认 `http(s)` 直链、最多 12 条。

### 2.4 无服务端体验 / 联调

```bash
python tools/ws-demo.py          # 监听 8787：终端表 + token 鉴权 + 路由投递 + 媒体样例
python tools/ws-demo.py --quiet  # 只等 HTTP 指令（服务端驱动测试用）
# 客户端填 127.0.0.1:8787，token 用 ect_demo_alpha
```

它是协议的最小参考实现（握手/鉴权/路由/回执/动作回传），可直接当服务端骨架照抄。

## 三、检查清单

**新用户上线**：地址填对 ✓ → 激活码入网（气泡弹「已待命」）✓ → 让管理员推一条测试通知 ✓

**新服务端接入**：WS 握手 101 ✓ → hello/hello_ack 回 terminal_id ✓ → subscribe 回显 topics ✓ → notice 帧到达且气泡渲染 ✓ → action 上行回执（ack）✓

**出问题的分层排查**：网络（地址通不通）→ 鉴权（401/4001/4003/4029，见 1.3）→ 订阅（帧日志无帧）→ 字段（有帧无气泡，帧日志对照 2.3 形状）
