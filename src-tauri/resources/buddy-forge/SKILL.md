# buddy-forge — EchoCast 形象定制

把「一句风格想法」变成「EchoCast 客户端里能切换的完整形象包」。
全流程五步：**定风格 → 生图 → 管线加工 → 装机 → 切换验证**。

## 形象包长什么样

```
<包名>/
  manifest.json     帧尺寸、基线、动作清单
  idle.webp         待命（必填）
  success.webp      任务完成（必填）
  fail.webp         任务失败（必填）
  running.webp      执行中（可选，缺了回退 idle）
  idle_blink.webp   眨眼帧（可选）
  hover.webp        鼠标悬停表情（可选）
  sleep.webp        久无交互（可选）
```

- 动作是**静态单帧 WebP（256×256，透明底）**，动画全部由 CSS 编排（呼吸缩放、两层交替眨眼）。不要做逐帧序列/GIF——GIF 是 1-bit alpha 会带白边，逐帧体积翻十倍。
- 必填动作缺一个整包判为不合格，客户端不会显示它。

## 前置

```bash
python -m pip install pillow numpy
```

## 第 1 步：定风格

两套已验证的风格模板，任选其一或自己写（约束条件不能删，见 references/prompt-template.md）：

| 风格 | 适合 | 要点 |
|---|---|---|
| 扁平矢量小生物 | 简洁、小尺寸清晰 | 2px 深色描边、≤3 色、钝角 |
| 3D 哑光小机器人 | 立体感（现内置 robot 就是这种） | 白色哑光材质、护目镜屏幕脸、圆角关节、禁高光反射 |

`python scripts/forge.py prompt --species <形态> --color <主色>` 可生成 7 个动作的提示词骨架。

**角色设定写一段固定描述并全程复用**（外形/比例/材质/配色），后面每张图只换动作行——这是六个动作长得像同一只角色的第一道保险。

## 第 2 步：AI 生图（用 ImageGen 工具）

1. **文生图出 idle 帧**：把 idle 提示词交给生图模型，1024×1024。
   背景要求「纯洋红 #FF00FF 平涂」。不要写「透明背景」——模型会画棋盘格假透明；也别指望 `background: transparent` 参数，实测会被忽略。
2. **图生图出其余动作**：把 idle 图作为参考图，提示词开头固定写
   「保持原图中这只角色的外形、比例、材质、配色完全一致，只把动作改为：<动作描述>」。
   每个动作一次，命名 `idle.png / success.png / fail.png / running.png ...` 放进同一目录。
3. 洋红背景为什么必须：白底会被白色角色吃掉、绿幕会被绿色角色吃掉，洋红几乎不参与角色配色。
4. 生成的图存到一个工作目录，如 `./raw/<包名>/`。

## 第 3 步：管线加工

```bash
# 整包处理（在 EchoCast 仓库里跑则直接出到 src/buddies/builtin/<包名>/）
python scripts/forge.py pack --src raw/<包名> --name <包名> --display 40

# 校验（尺寸/alpha/体积/必填动作）
python scripts/forge.py check --dir <输出目录>

# 对版图（贴纸色底 + 画基线，肉眼查粉边与错位，每次必看）
python scripts/contact_sheet.py --dir <输出目录> --out preview.png
```

管线每张图自动做：四角采样键色 → 洋红色键抠图（模型给的洋红不是纯 #FF00FF，实测 (190,28,136)，所以必须现场采样）→ 清右下角水印区 → despill 去粉边 → alpha bbox 裁切 → 缩放到 256px 画布、底边对齐基线 → WebP q85。已带透明通道的图自动跳过色键。

## 第 4 步：装机（二选一）

| 方式 | 位置 | 适合 |
|---|---|---|
| 内置包（改代码） | `<仓库>/src/buddies/builtin/<包名>/` | 开发者；构建期自动发现，`manifest.json` 加 `"primary": true` 可设为默认 |
| 用户包（免安装） | `%APPDATA%\com.echocast.client\buddies\<包名>\` | 终端用户；目录不存在就手动创建，客户端启动时自动扫描 |

用户包里的 manifest.json 直接从内置包复制改 `pack` 字段即可（动作表、frame=256、baseline=245 保持一致，除非自改管线参数）。

## 第 5 步：切换验证

重启 EchoCast（或重新打开设置面板）→ 设置面板「形象包」区出现新包 → 点选 → 右下角气泡与顶部灯条立即换装。
验证清单：
- 四种状态气泡各看一眼：success/fail/running/idle 形象都对
- 对版图上六帧脚底在同一基线、大小一致、无粉边
- 灯条 44px 小头像下手脚和天线仍然清晰（太糊就要提高对比度或加粗描边）

## 三条硬规则（踩坑换来的）

1. **脚底对齐，不要垂直居中**。生图里主体位置每次不同，按画布中心裁会让角色播放时上下跳。所有帧共享 baseline。
2. **姿态靠形状差异，不靠位移**。「身体下移」表达沮丧会被裁切对齐抹平；要写「身体变矮 + 肩膀下垂 + 嘴角下弯」。
3. **举手不要高过头顶太多**。缩放按 bbox 高宽取小值，手举太高那一帧整体变小，同套动作出现大小跳变。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| alpha 全空 | 背景不是纯洋红平涂，或角色本身含洋红 | 重生成，模板里「纯色平涂」重复强调 |
| 边缘一圈粉 | despill 阈值 | `forge.py` 的 `keyout(inner=45, outer=135)` 方向调 |
| 某帧角色偏小 | 手臂/装饰撑大了 bbox | 见硬规则 3 |
| 六张画风不一致 | 角色描述没复用 | 图生图 + 固定同一句角色描述，参考第 2 步 |
| 单张 >60KB | 细节太多 | `--quality 78`，或减少配色/纹理 |
| 眼睛有高光点 | 生图默认加反光 | 提示词加「哑光眼球，无高光反射」 |

## 设计红线

角色**不跟随主题染色**。位图 hue-rotate 会连带污染眼睛和描边——形象是产品的人格，不属于任何主题。
